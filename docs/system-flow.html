Part 2 · Developer Flow

ภาพรวมระบบสำหรับนักพัฒนา

3 service บน Railway ในโปรเจกต์เดียว เบราว์เซอร์คุยกับเว็บเท่านั้น ส่วนเว็บส่งต่อ /api ไปยัง API จากฝั่ง server ทำให้ session cookie เป็น first-party และไม่ต้องเปิด CORS

ลำดับการประมวลผล webhook

ลำดับนี้ห้ามสลับ — โดยเฉพาะข้อ 1 ต้องทำกับไบต์ดิบก่อน express.json จะ parse ไม่งั้นลายเซ็นไม่มีวันตรง และ "วิธีแก้" ที่เย้ายวนคือปิดการตรวจ

  1. ตรวจ X-Line-Signature ด้วย HMAC-SHA256 จากไบต์ดิบ เทียบแบบ constant timeลายเซ็นไม่มีหรือไม่ตรง → 401 ไม่เขียนแม้แต่ log row
  2. parse JSON แล้วตอบ LINE 200 ทันที งานที่เหลือทำหลังตอบbody ไม่ใช่ JSON → 400
  3. INSERT ลง line_webhook_events โดยใช้ webhookEventId เป็น primary key — ให้ constraint ตัดสิน ไม่อ่านเช็คก่อนเขียนชน primary key → เป็นการส่งซ้ำ ข้ามทั้ง event
  4. หาผู้ติดต่อจาก line_user_id ถ้าไม่มี ดึงชื่อจาก LINE profile แล้วสร้างใหม่
  5. หา lead ที่ยังไม่ปิดของผู้ติดต่อนี้ ถ้าปิดหมดแล้ว สร้าง lead ใหม่ขั้น New · ยังไม่มีเจ้าของ
  6. บันทึกข้อความขาเข้า + timeline message_received แล้วอัปเดตสถานะ event เป็น processed

สถานะที่ต้องรู้ก่อนแตะ logic

สิ่งที่ถูกบันทึกโดยไม่ต้องเขียนเอง

authorship

created_by / updated_by ทุกตาราง เขียนโดย Sequelize hook จาก actorId ที่ส่งมากับ query

audit history

ทุก update และ soft delete ลง tbl_audit_history พร้อม old_json / new_json · password_hash ไม่ถูกคัดลอก

snapshot

ข้อมูลผู้ติดต่อ บริษัท เจ้าของ ณ เวลานั้น เก็บเป็น *_data_json — ตอบได้ว่า "ตอนมอบหมาย บริษัทชื่ออะไร"

bulk update ที่จะหลบ audit hook ถูก guard ปฏิเสธนอก production — ถ้าจำเป็นให้ใช้ instance.update() หรือ individualHooks: true
